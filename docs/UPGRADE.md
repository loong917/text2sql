# 四阶段升级与验收边界

## 0.8.1 反例隔离与集合检索身份

本次追加两项整改：完整可解析的反例 SQL 纳入训练侧模板隔离；Chroma 集合证据升级为 v2，绑定记录内容、集合级检索配置和受控查询嵌入身份。不能仅修改问题、family 或 `syntax_error` 标签规避 held-out 隔离。真实解析失败且无可识别查询主体的单查询反例才可豁免模板，问题/查询族仍隔离；完整 SQL 追加损坏 WHERE/ORDER BY/GROUP BY/UNION、空分组等不完整 AST 均失败关闭，不自动修复后放行。

v1 集合证据不自动补字段，也不重新签名旧 Test。保留旧资产供追溯，完成独立 Gold 审核后导出新的 generation，重新构建候选、冻结 Test、检查及显式晋升；同输入重建时暂设 TRAINING_SKIP_UNCHANGED=false。配置变化、证据缺失或不匹配均失败关闭，不切换 ACTIVE。

代码整改不生成真实业务审批：38 candidate / 0 approved 仍是当前实际数据状态，依赖风险、目标库/模型评测、镜像、HTTPS、压力与恢复验收仍按生产清单阻断。

## 0.8.0 学习、评测与正式晋升隔离

0.8.0 是发布契约升级，不沿用 0.7.0 的校准器或发布证据，也不自动迁移待审核样本为已批准。

| 整改 | 当前契约 |
| --- | --- |
| 生产知识审核 | 源业务知识与冻结快照使用相同的当前 Schema/双人审核要求；拒绝空白粒度、占位单位和内容变更 |
| 固定训练输入 | 数据集、目录、校准器只读取一次；消耗与摘要同源，提交前复核文件、Schema、模型和业务目录 |
| 防同形泄漏 | SQL 模板按 Scope 规范化；同形投影/CTE/别名变体不因名称不同混入 held-out；canonical 与派生 generation 逐项比对 |
| 实际集合证据 | training_manifest 的 collection_evidence 绑定精确文档、metadata、向量和注册索引；训练、评测、发布、runtime 复核 |
| 无损结果契约 | AST 提前拒绝重复输出名；执行、反馈、评测共享列名/行结构检查，转换前防止重复键静默丢列 |
| 候选与上线 | build_candidate 只 stage；Test 写版本目录；check-only 不修改 ACTIVE/审批；显式 --promote 才原子切换 |

升级顺序：完成真实 Schema/知识/Gold 审核 → 同代 generation → 重新拟合 v2 检索校准器 → 构建候选 → 用 --artifact VERSION 评测 Test → 只读发布检查 → 显式晋升并重启。命令和故障操作见 [运营手册](OPERATIONS.md)。

已批准版本的 Test/审批不重写；同输入需要新候选时临时设置 TRAINING_SKIP_UNCHANGED=false。训练、评测、晋升共用锁，锁老化不证明进程已结束；不得自动抢锁。晋升中断留下审批但未切 ACTIVE，不算上线，保留诊断并重新构建独立候选。

Dev 输出必须为独立 JSON，不得覆盖输入、产物或 Chroma。发布诊断/归档同样受路径保护；默认 Chroma 根目录只保留两个约定诊断文件的写入例外，任意自定义报告请放在独立报告目录。私有 .env、真实数据库和业务批准记录不由代码升级代填。

## 0.7.0 知识与 Gold 治理整改（历史）

完整 Schema 合同、可信单列 FK、唯一键证明、指标/策略类型、审核内容摘要和双人证据、只读限行基准已统一。v3 合同移入 Domain 供知识与评测共享，删除旧复制模块。canonical Gold 已迁入 38 条待审资产并保留原字节；不可变导出、训练/Prompt隔离和生产 generation 门禁落地。

这是破坏性治理升级：旧残缺快照、部分语义 IR、只有 approved 标签的数据和旧发布证据均不能沿用。按 [Gold 手册](GOLD_SET.md) 重新取得真实结构、单位/粒度审核和执行证据；未批准任何实际 Gold 或数据库 DDL。

## 本轮验证

已完成本地单元、集成、行为契约与 HTTP 回归；Ruff、Mypy、JS 语法与锁文件检查通过。wheel 在仓库外安装并校验包资源、身份及健康接口。

这些测试使用本地夹具，不是目标数据库/模型的准确率报告。上游 Starlette/HTTPX 与 Vanna/Pydantic 仍有弃用告警；没有修改第三方库来掩盖告警。

## 未完成的生产验收

1. 在目标 SQL Server 验证证书、TLS 与真实有效权限，检查元数据可见性和查询取消行为。
2. 在目标 Ollama 验证模型 digest、结构化输出、真实查询准确率、延迟和并发。
3. 扩充人工审核且模板隔离的 Test 与检索数据到生产最低规模；重新训练和冻结评测。
4. 在目标 Docker/HTTPS 环境验证镜像、持久卷、备份恢复与回滚；CI 新增检查尚需实际执行。

保守规则解析不能证明开放式语言的完备性，未知约束会提高澄清率。后续以真实难例评测覆盖与错误拒答权衡，再扩展解析、编译和验证能力；不要为了“能回答”绕过现有门禁。

因此，本轮是代码升级与离线质量验收完成，不是已批准生产上线。
