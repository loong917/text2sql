## 0.8.1 整改范围与验收边界

本轮落地的代码保护不等于正式生产批准：

| 整改项 | 必须满足的合同 |
| --- | --- |
| 生产知识可信度 | 源目录和冻结快照都验证内容/Schema 绑定的人审；发布时冻结业务知识必须与已审核 generation 一致 |
| 输入单次读取 | 结构化知识、Gold/检索数据、校准器从固定字节解析并计算摘要；结束及发布前复验文件、目录清单、Schema 和模型身份 |
| Gold 派生真实性 | 从 canonical 重新计算派生记录，不能只更新 manifest 摘要；SQL 模板按 Scope 规范化，可解析反例也隔离跨 split 的同形查询，伪造 syntax_error 标签不能豁免 |
| 实际集合证据 | v2 将实际 ID、document、逐条 metadata、embedding 与集合级检索配置绑定；训练、评测、发布、运行核对内容/配置摘要及受控查询嵌入身份；拒绝旧 v1 |
| 输出结果完整性 | AST 最终列名和实际表格结果均禁止重复输出名；转换成行字典之前校验，避免重名列静默覆盖 |
| 候选与上线隔离 | train 仅 stage；Test 写本版本 test_report.json；检查默认不晋升，只有显式 --artifact VERSION --promote 能写审批并切换 ACTIVE |

Test、晋升与训练共用独占 lease；检测到疑似过期锁也不自动抢占。已批准版本的 Test 和审批不得原地重写。普通 release-check 即使失败也只写诊断，不删除旧审批或更改 ACTIVE。

ACTIVE 的 release_manifest_path 必须指向所属版本 approved_release.json，审批里的 test_report_path 必须指向同版本 test_report.json；可变的公共归档不是运行时批准源。readiness/归档输出不能覆盖数据输入、知识目录、注册产物或服务指针。晋升先写版本审批，再原子切换指针；输入变化或最终身份复验失败时保持旧 ACTIVE，候选不算上线。

这些检查不具备对外部敌意写者的事务隔离能力。生产仍须用文件权限、单写者 Chroma 和不可变模型 tag 保护冻结窗口；模型前后 digest 相同不能证明逐次请求绝无 ABA 变化。真实数据库数据快照同样需要目标环境保证。

0.8.1 的测试统计、wheel/镜像 digest 和目标环境签字应来自本轮实际产物，不能沿用下方历史数字。真实 Gold 仍为 38 candidate、0 approved，不能将合成夹具或 candidate 标成正式验收数据。旧 v1 集合证据不自动补字段或重签，重新构建候选并冻结 Test 后再检查、显式晋升。

## 已落实的代码整改

| 风险 | 实现与验收方式 |
| --- | --- |
| 比较符号被吞掉、多个日期只取一个 | 比较符号统一进入阈值槽；未消费数字、比较条件或时间组合要求澄清；负数阈值也通过编译/校验回归 |
| SELECT DISTINCT COUNT(*) 冒充去重统计 | 未明确去重键时要求澄清，不能编译为无意义的聚合结果去重 |
| AST 将 (A AND B) OR C 误认成 IN | 仅证明纯同列成员 OR；嵌套 AND 的分支拒绝；内存数据库反例验证结果确实不同 |
| 重复引用 CTE 放大聚合输入 | 按关系出现次数计数，不按定义 Scope 去重；拒绝多出的关联 |
| 表采样、汇总行、表提示改变结果 | 未声明的 TABLESAMPLE、ROLLUP/CUBE、表提示和 SELECT 修饰符不进入已证明能力范围 |
| 未登记检索内容进入 Prompt | 必须精确命中冻结索引；渲染阶段再次校验，取消“包含候选表名即可接受”的后备路径 |
| 在线 Gold 改变已评测生产提示词 | 生产只读冻结示例；审核反馈要重建、评测与发布后生效；相对日期不能晋升长期 Gold |
| 评测只执行少数正例仍达标 | 冻结正例必须明确要求执行，执行覆盖率和完整基准一致率以全部正例为分母 |
| 不完整语义证据冒充 100% 正确 | 完整 v3 快照包含阈值、排序指标、状态、否定和相对时间参考日；旧版、子集和弱类型被拒绝 |
| 独立解析计划冒充实际查询计划 | 比较本次查询返回的计划证据；缺失、畸形或被替换的计划不能使用独立重解析补造通过 |
| 校验内容与最终文件摘要不一致 | 同一字节快照解析/摘要，校验结束及发布前复验源数据、产物、指针和身份 |
| 同步反馈或门禁阻塞事件循环 | 显式线程边界处理同步存储与发布门禁；关闭所有资源后汇总异常，保留取消信号 |
| 多 Schema 检索标注丢失命名空间 | 从查询 Scope 提取真实物理表，保留非 dbo Schema，排除 CTE 别名且处理同名碰撞 |
| 构建后端隐式解析漂移 | 固定后端版本及文件 SHA-256，Docker 禁用构建隔离；构建锁文件纳入分发与发布身份 |
| 管理员 Cookie 绕过同源校验 | 查询与管理员写请求统一验证 Origin/Fetch Metadata；跨源、缺少证明、畸形签名会话的 HTTP 反例 |
| 非 ASCII Key 触发 500、会话字段弱类型 | UTF-8 字节常量时间比较；会话字段严格类型/长度/结构校验 |
| 指标 ID 相同但实际物理绑定错误 | 对实际 QueryPlan 核对目录聚合/表/列/维度/实体/日期/关联，不用独立解析补造 |
| 字符串实体隐式等同数字 | AST 成员与谓词证明保留字面量类型；001、1、1.0 和字符串实体的反例 |
| SQL 格式化损坏字面量或行注释 | 仅去外围空白与围栏；反馈签名保留字面量区别；历史 Gold 须重新审核 |
| 评测文件 ABA 与混合输入 | 数据单次字节读取，受控产物冻结副本，结束及发布前身份复验 |
| 冷索引阻塞、延迟初始化竞态/资源泄漏 | 工作线程加载与 single-flight；资源工厂加锁/关闭守卫；明确集合；关闭 SQL 池、知识工作线程和 embedding HTTP |
| 依赖只核对部分包、Python 平台不绑定 | 从哈希运行锁建立完整适用依赖清单；偏离即拒绝，Python 实现/版本/平台加入身份 |
| 可用依赖安全补丁未应用、CI 信任漂移 | urllib3/OAuthlib 定向升级；Actions 固定 SHA、只读权限、扫描失败关闭和证据上传 |
| 本地问题/Schema 经代理误转发、Ollama 502 | HTTP 回环客户端统一不继承环境代理；生成/两类嵌入/预检契约覆盖，项目模型只读预检通过；远程/HTTPS 保留原行为 |

这些保护是有限能力的正确性门禁，不是任意自然语言/SQL 等价的数学证明。受支持计划优先确定性编译，扩展能力必须同步更新解析、编译、校验和评测。

| 性能/稳定性 | 在目标硬件定义并验证 p95/p99、吞吐、排队上限、错误率与事件循环延迟；做长时运行和重启演练 | 压测报告、服务 SLO、报警配置 |
| 回滚/恢复 | 代码、模型、知识、报告、指针整套回滚，备份可恢复；运行时版本切换后重启 | 演练记录、恢复耗时与数据一致性报告 |

生产最低准确率门槛是下限，不是自动适用于所有业务的承诺。重要指标口径应由业务负责人设定更高阈值并签字；只看平均通过率会掩盖困难场景缺陷。

## 推荐执行顺序

1. 冻结 0.8.1 代码/依赖与目标配置，核验本轮质量门禁和分发测试；先解决未处置依赖风险、数据库 TLS/只读配置、生产密钥与 HTTPS，并完成真实 Schema/业务/Gold 审核与不可变导出。
2. 收集真实审核数据，迁移完整 v3 语义预期；相对时间验收要显式核对本次参考日与基准边界，长期 Gold 改为绝对日期。
3. 在目标 SQL Server/Ollama 重新校准检索、训练候选，用 --artifact 明确选择同一版本完成冻结 Test 和 release-check；未通过时保持未就绪，检查通过也不会自动晋升。
4. 在目标 HTTPS/容器环境完成性能、取消、备份、回滚和安全验收；签字后显式 --artifact VERSION --promote，重启并核验 /readyz，通过后小流量灰度。

不删除旧活动数据，不沿用旧发布清单，不为了就绪关闭 AST/语义或数据规模检查。

## 可扩展性与维护路线

- 当前优先受控单租户/单实例上线。多实例前，将反馈持久化与检索存储变为独立服务，并通过现有 Repository/KnowledgeMemory 端口替换适配器；不要把本地 SQLite/Chroma 共享写入等同于高可用。
- 多用户/多业务域前，增加用户身份、领域授权、数据行级范围和审计归属；共享 API Key 不能替代个人身份或租户隔离。
- 收窄 SqlExecutor/Repository/Validator 中仍存在的 Any，使用明确结果与反馈证据类型；保持架构依赖测试、异常契约和真实依赖集成测试。
- 当前已增加实际计划对权威目录的物理绑定核验，但业务目录本身仍需人工审核；未来扩展复杂指标/关联时增加独立物理预期和真实结果反例，不能用 v3 快照通过替代 AST 与完整基准对比。
- 在真实难例中驱动能力扩展；相对时间、去重键、比例、跨事实表和窗口语义须单独定义，不能只扩 Prompt。

同步代码与异步接口的边界依据 [FastAPI 官方并发说明](https://fastapi.tiangolo.com/async/)；构建隔离与后端安装依据 [pip 官方说明](https://pip.pypa.io/en/stable/cli/pip_install/#pep-517-and-518-support)。这些资料不代替本项目的目标环境验收。
